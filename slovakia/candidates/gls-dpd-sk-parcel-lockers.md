## Try it

- **Map preview:** none, because the licence is unclear, so no extract is redistributed here.
- **QGIS (DPD):** save https://pickup.dpd.cz/Export/csv?country=703 as `dpd_sk.csv` (tested 2026-09-30, 3,903 rows). Then *Layer → Add Layer → Add Delimited Text Layer…*: CSV, comma, UTF-8, X = `longitude`, Y = `latitude`, EPSG:4326. `pickup_network_type` separates `dpd_box` from `pickup_point`, and `company` gives the network ("DPD Pickup Box", "AlzaBox …", "Z-BOX …").
- **QGIS (GLS):** convert the JSON to CSV first:
  ```
  curl -s https://map.gls-slovakia.com/data/deliveryPoints/sk.json | python3 -c "import json,csv,sys;w=csv.writer(open('gls_sk.csv','w'));w.writerow(['id','name','type','provider','lat','lon']);w.writerows([i['id'],i['name'],i['type'],i.get('parcelLockerExternalProvider'),*i['location']] for i in json.load(sys.stdin)['items'])"
  ```
  Then add `gls_sk.csv` as a delimited text layer (X = `lon`, Y = `lat`, EPSG:4326).
- **Web viewers:** https://pickup.dpd.cz/ (switch to Slovakia) and the GLS SK ParcelShop search on gls-group.com.

## Notes

- **Gap:** Postpass spatial check on 2026-09-30. Each check drew 300 random lockers from a network and looked for an OSM `amenity=parcel_locker` within 50 m.

  | Network (feed) | Feed | Same brand ≤ 50 m | Any locker ≤ 50 m | Missing (estimate) |
  |---|---|---|---|---|
  | GLS Balíkomat (GLS) | 773 | 61 / 300 (20 %) | 141 / 300 | **~620** |
  | AlzaBox (GLS feed) | 1,220 | 120 / 300 (40 %) | 144 / 300 | **~730** |
  | DPD Pickup Box (DPD) | 453 | 45 / 300 (15 %) | 107 / 300 | **~385** |

  Z-BOX (1,189 in the DPD feed) is already in Sync and was not re-checked. "Box Sl. Pošty" is Slovenská pošta's BalíkoBOX, which ATP covers (`slovenska_posta_sk`, 243).
- **Stable ids:**
  - GLS `id` (for example `SK01001-PARCELLOC008`, `SK01001-PLOCKER009`) is the ParcelShop id that e-shops pass to GLS. `goldId` and, on AlzaBoxes, `externalId` (for example `3034`) are also present.
  - DPD `id` (for example `SK22030`) is the DPD pickup id.
  - None of the 100 OSM AlzaBoxes with a `ref` in the SK bbox matched a GLS `externalId`, so existing AlzaBox refs are a different scheme. Use a namespaced `ref:gls` or `ref:dpd` if a carrier id is stored on a locker that the carrier does not own.
- **AlzaBox is the biggest missing network after balíkovo.** Alza's own AlzaBox API needs OAuth partner credentials (noted in the Czech candidate `dpd-pickup-cz.md`), so these carrier feeds are the open-access lists. The GLS and DPD AlzaBox counts (1,220 and 1,307) differ slightly. Take the union, deduplicating by position.
- **Operator oddity in OSM:** 468 lockers in the SK bbox carry `operator=GLS General Logistics Systems Hungary Kft.`. They are in Hungary (the bbox overlaps it). This is a reminder to clip matches to relation 14296.
- **Coverage:** no ATP spider for GLS SK or DPD SK (`dpd_de` covers Germany only), and Sync has neither.
- **Czech twins:** `candidates/gls-cz-parcel-box.md` and `candidates/dpd-pickup-cz.md` in the Czech track use the same endpoints with `cz.json` / `country=203`. A consent from the GLS or DPD group could cover both countries.
- **Tagging:** Tag:amenity=parcel_locker (wiki, raw, read 2026-09-30) marks `brand` as important and lists `operator`, `ref` and `parcel_mail_in`. Do not put the id in `name`. The brand values above are the ones already dominant in SK OSM data.
- **ZBGIS:** the catalogue has no object type for parcel lockers.
- **Contacts:** GLS General Logistics Systems Slovakia s.r.o. (https://gls-group.com/SK/); DPD Slovakia (https://www.dpd.com/sk/).
